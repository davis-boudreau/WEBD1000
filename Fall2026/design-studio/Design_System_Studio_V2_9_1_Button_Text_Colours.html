NSCC official colour palette

Exact HEX values from the NSCC Visual Identity Guidelines. Three primary colours and eight accent colours. These are brand swatches, not interchangeable CSS semantic roles.

Primary brand colours

Accent brand colours

Important distinction:
  • Brand primary describes NSCC's official white, blue and dark grey palette.
  • CSS --primary describes the interface's main action colour; its default is NSCC blue.
  • Brand accent describes eight approved colours; select one to feature in a UI component.
  • Generated ramps are teaching aids derived from an official swatch; they are not official additional brand colours.
  • Contrast and meaning: an official brand colour is not automatically accessible as text or a button background.

Reference: NSCC Visual Identity Guidelines (PDF). This classroom tool is an educational prototype, not an official NSCC website template.

1. Colour systems

Each ramp has 11 steps. The centre step (500) preserves your chosen HEX value.

RGB mix

Semantic colour roles

How does the ramp generator work?
  • RGB Mix: interpolate each red, green and blue channel toward white for lighter steps, or black for darker steps. Round channels to whole numbers.
  • OKLCH: convert the anchor to perceptual lightness, chroma and hue; vary lightness and gently reduce chroma at the extremes; convert back to sRGB while reducing out-of-gamut chroma.
  • Neither method automatically guarantees contrast or an attractive palette. Review each role and theme.
  • Secondary and accent colours are independently chosen in V2; harmony suggestions are planned for a later iteration.

Accessibility and semantics:
  • :hover, :active and :focus-visible are real CSS pseudo-classes. The matrix uses labelled simulations for side-by-side inspection.
  • Use native <button> and the disabled attribute for unavailable actions.
  • aria-pressed belongs on toggle buttons only. Ordinary submit buttons do not need it.
  • Loading requires application logic, accessible status messaging and duplicate-submission prevention; CSS alone cannot provide that behaviour.
  • Test contrast in both themes and with every hover/active colour. Reduced-motion preferences disable nonessential transitions.

5. Accessibility quick checks
WCAG 2.x text contrast: 4.5:1 for normal text and 3:1 for large text. This checker measures selected colour pairs only; it does not certify accessibility.
Also verify focus visibility, keyboard use, 200% text resize, content reflow, non-text contrast and meaning conveyed without colour.

7. Classroom workflow
  1. 03A — Colour: configure NSCC primary, supporting and accent colours; compare RGB Mix/OKLCH; review semantic tokens and contrast.
  2. 03B — Typography: configure a font stack, modular scale and leading; recreate the mobile and desktop scale in Figma.
  3. Responsive implementation: inspect CSS Grid, Flexbox, clamp(), spacing, radius and component states.
  4. Project handoff: save JSON and export commented CSS; integrate and adapt the code in your own project.
  5. Reflection: explain your choices and provide evidence of Figma work, testing and Git commits in Brightspace.
This is a learning tool, not a substitute for design reasoning, Figma deliverables, implementation or formal accessibility testing.
