## 🧭 **WEBD 1000 – Outcome 1: Evaluate a Variety of Websites for Usability and Accessibility**

### Expanded Quiz Feedback & Learning Explanations

---

### **1. Perceivable (POUR Principle)**

**Correct Answer:** *Perceivable*

**The full POUR principle:**
Accessibility is built on four foundational principles:

* **P – Perceivable:** Information must be presented so all users can sense it (see, hear, or feel).
* **O – Operable:** Users can operate interface controls.
* **U – Understandable:** Content and operation must make sense.
* **R – Robust:** Content must work across technologies and remain reliable.

**Explanation:**
“Perceivable” ensures content can be detected by all users. For instance, text alternatives (alt text), captions, and contrast make visuals and audio understandable to people with visual or auditory impairments.

**Why others are wrong:**

* **Operable:** Focuses on interaction (ability to use keyboard or mouse).
* **Understandable:** Ensures users can comprehend layout and language.
* **Robust:** Relates to compatibility with assistive tech and future-proof design.

---

### **2. WAVE Accessibility Checker**

**Correct Answer:** *WAVE Accessibility Checker*

**Explanation:**
WAVE visually marks accessibility errors and warnings right on your page—such as missing alt text, color contrast failures, and structural issues. It’s fast, free, and ideal for learning.

**Why others are wrong:**

* **Canva:** A design tool, not an evaluator.
* **FileZilla:** Used for FTP file transfer, unrelated to accessibility.
* **Photoshop:** A graphics editor, not a validation tool.

---

### **3. WCAG Definition**

**Correct Answer:** *Web Content Accessibility Guidelines*

**Explanation:**
WCAG, developed by W3C, defines success criteria (A, AA, AAA) for accessible design worldwide. It forms the legal baseline for accessibility compliance.

**Why others are wrong:**

* **Website Coding and Graphics:** Describes no standards.
* **Web Compliance and Governance:** Not an official framework.
* **Web Creator Advisory Group:** Fictional name.

---

### **4. 4.5 : 1 Contrast Ratio**

**Correct Answer:** *4.5 : 1*

**Explanation:**
WCAG 2.1 AA requires a 4.5 : 1 ratio for body text < 18 pt. This ensures readability for users with low vision or color deficiency.

**Why others are wrong:**

* **3 : 1:** Only valid for *large* text (≥ 18 pt).
* **2 : 1 / 7 : 1:** Too low / AAA level (more stringent than required).

---

### **5. The `alt` Attribute**

**Correct Answer:** *alt*

**Explanation:**
The `alt` attribute describes images for screen readers or if the image doesn’t load. Always describe purpose, not appearance (e.g., “Corah logo,” not “purple swirl”).

**Why others are wrong:**

* **title:** Adds tooltips for sighted users, not accessibility text.
* **src:** Defines the image file location.
* **id:** Used for scripting or CSS reference.

---

### **6. Keyboard Navigation**

**Correct Answer:** *Allows users who cannot use a mouse to navigate and interact*

**Explanation:**
Operable design ensures all features are accessible with the keyboard alone (Tab, Shift + Tab, Enter). Essential for blind or motor-impaired users.

**Why others are wrong:**

* **Text alignment / load time / visual clutter:** Performance or styling issues, not accessibility.

---

### **7. “O” = Operable (POUR)**

**Correct Answer:** *Operable*

**Explanation:**
“Operable” ensures interactive components can be accessed, understood, and used — through keyboard controls, focus order, and sufficient time.

**Why others are wrong:**

* **Organized / Objective / Optional:** Not WCAG principles.

---

### **8. Usability Heuristic**

**Correct Answer:** *A general principle for evaluating user interface quality*

**Explanation:**
Heuristics like “Consistency and standards” or “Error prevention” guide designers to create intuitive, learnable interfaces.

**Why others are wrong:**

* **Browser debugging / color-contrast / coding standard:** Technical concepts, not evaluation principles.

---

### **9. Unlabeled Icons = Poor Usability**

**Correct Answer:** *Unlabeled icons and hidden controls*

**Explanation:**
Icons without text confuse new users and screen-reader users. Hidden elements without clues break discoverability.

**Why others are wrong:**

* **Consistent menus / Readable text / Heading hierarchy:** All improve usability.

---

### **10. Black Text on White**

**Correct Answer:** *Black text on white background*

**Explanation:**
This combination offers optimal readability and WCAG-compliant contrast.

**Why others are wrong:**

* **Yellow on blue / red on green:** Poor for color-blind users.
* **Light gray on white:** Fails contrast ratio standards.

---

### **11. Usability Testing**

**Correct Answer:** *Observe users completing real tasks to find obstacles*

**Explanation:**
Watching real users perform realistic tasks exposes navigation or comprehension issues not found by automated tests.

**Why others are wrong:**

* **Validate HTML:** Technical check only.
* **Reduce image size / file naming:** Performance or maintenance tasks.

---

### **12. “U” = Understandable (POUR)**

**Correct Answer:** *Understandable*

**Explanation:**
Interfaces and content must make sense—consistent navigation, plain language, clear instructions, and predictable interactions.

**Why others are wrong:**

* **Perceivable / Operable / Robust:** Other POUR principles addressing different aspects.

---

### **13. Descriptive Link Text**

**Correct Answer:** *Download Program Guide (PDF)*

**Explanation:**
Link text should stand alone, describing its destination. “Click here” is meaningless when read out of context by screen readers.

**Why others are wrong:**

* **Click here / More info / Read this:** No semantic meaning.

---

### **14. Flashing or Strobing Content**

**Correct Answer:** *Seizure or vestibular trigger*

**Explanation:**
Flashing faster than 3 times/sec can trigger seizures; motion can cause nausea. Use still images or give users control.

**Why others are wrong:**

* **Contrast / alt / labels:** Unrelated accessibility categories.

---

### **15. Heading Structure**

**Correct Answer:** *Provide document structure and hierarchy*

**Explanation:**
Proper heading order (<h1>→<h2>→<h3>) defines logical structure and enables screen-reader navigation.

**Why others are wrong:**

* **Font color / speed / animation:** Purely visual effects.

---

### **16. “R” = Robust (POUR)**

**Correct Answer:** *Robust*

**Explanation:**
Content must be compatible with current and future tools (browsers, screen readers). Semantic HTML and valid code preserve meaning.

**Why others are wrong:**

* **Readable / Responsive / Relevant:** Important traits but not POUR principles.

---

### **17. Avoid Color-Only Meaning**

**Correct Answer:** *Avoid using color alone to convey meaning*

**Explanation:**
Color-blind users may not perceive differences. Combine color with text or icons (e.g., “Required *”).

**Why others are wrong:**

* **Saturated / gradients / reduced contrast:** Do not guarantee accessibility.

---

### **18. Alt Text Behavior**

**Correct Answer:** *Displays the text alternative to describe the image*

**Explanation:**
If an image fails to load or a user relies on a screen reader, the alt text conveys purpose and meaning, maintaining comprehension.

**Why others are wrong:**

* **Blank space / file path / audio playback:** Incorrect behavior.

---

### **19. Responsive Design’s Accessibility Benefit**

**Correct Answer:** *Content remains usable on all screen sizes and devices*

**Explanation:**
Responsive layouts adapt to different viewports, ensuring readable text, reachable buttons, and usable navigation across devices and zoom levels.

**Why others are wrong:**

* **Animations / hidden info / bandwidth:** Unrelated or negative effects.

---

### **20. Consistent Layout**

**Correct Answer:** *Users know where to find information and controls on every page*

**Explanation:**
Consistency supports predictability and cognitive ease—essential for neurodiverse and elderly users.

**Why others are wrong:**

* **Colorful / fast / randomized:** Aesthetic or negative impacts on usability.

---

### **21. Lighthouse Tool**

**Correct Answer:** *Lighthouse*

**Explanation:**
Google Lighthouse audits performance, accessibility, SEO, and best practices in Chrome DevTools.

**Why others are wrong:**

* **Dreamweaver / GitHub Pages / InVision:** Editing or hosting tools, not accessibility analyzers.

---

### **22. Primary Goal of Accessibility**

**Correct Answer:** *Ensure equal access and usability for all users regardless of ability*

**Explanation:**
Accessibility means *inclusivity*: designing so that everyone—blind, deaf, motor-impaired, or neurodiverse—can access and use your content.

**Why others are wrong:**

* **File size / visual effects / SEO:** Secondary benefits, not core purpose.

---

### **23. Alt Text and SEO**

**Correct Answer:** *Search engines use it to understand image content*

**Explanation:**
Alt text serves dual purposes: accessibility for humans, and context for search-engine indexing.

**Why others are wrong:**

* **File size / layout / animation:** Unrelated to alt text.

---

### **24. Clear Headings and Chunked Content**

**Correct Answer:** *Clear headings and chunked content*

**Explanation:**
Breaking text into logical sections helps users with cognitive or attention differences. Clear visual hierarchy benefits all readers.

**Why others are wrong:**

* **Flashing / dense text / endless scroll:** Increase cognitive load and disorientation.

---

### **25. Accessibility as Part of Usability**

**Correct Answer:** *Because a website is not usable if people with disabilities cannot use it*

**Explanation:**
Accessibility and usability are inseparable—if any group is excluded, the design has failed. Inclusive design enhances usability for *everyone* (e.g., captions help in noisy rooms).

**Why others are wrong:**

* **Color harmony / shorter text / server speed:** Peripheral to accessibility or usability.
